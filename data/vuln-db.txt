# system-administration — local vulnerability and support-status database
#
# This file is compiled into the binary so the checker works air-gapped. A file
# with the same format placed next to the executable, or at the path given by
# SYSADM_VULN_DB, is loaded on top of it and takes precedence, which is how the
# database is kept current without a rebuild and without network access.
#
# Format, one record per line, pipe separated:
#
#   kind|product|fixed_in|severity|id|description
#
#   kind      pkg  installed package, matched by name
#             svc  running service, matched by the version banner
#             os   distribution release, matched by id and version
#   product   package, service or distribution id (lowercase)
#   fixed_in  first version that is NOT affected; anything lower matches.
#             Write `from..fixed` when only a range of versions is affected, so
#             an older stable branch that never carried the flaw is not
#             reported just for being numerically lower. This matters: the
#             remedy distributions shipped for the xz backdoor was a downgrade
#             to 5.4.5, which a bare `5.6.2` bound would flag as vulnerable.
#             For `os` records this is the release that is out of support.
#   severity  critical | attention
#   id        CVE identifier, or EOL for support-status records
#
# Matching is by version number alone. Distributions routinely fix a CVE with a
# backported patch and no version bump, so a match here is a prompt to check the
# package changelog, not a verdict. Conversely, a branch outside the recorded
# range is not reported even if it is older, because that is the common case
# for a supported long-term release.
#
# Curated starter set of widely documented issues. Extend it with the advisory
# feed your organisation already trusts.
